# baturin_polka

Полка эталонов Бюро: готовые каркасы и исходники, не сырые «сделай красиво».

Один репозиторий. Ветка только `main`. Тип — папка, эталон — папка внутри типа.

## Дерево

```
etalons/index.yaml                 машина: полный список
etalons/README.md                  человек: таблица
TAXONOMY.md                        оси классификации
etalons/<page>/<id>/
  meta.yaml                        класс, когда брать
  USAGE.md                         как применять, что не клонировать
  site/                            канон: исходники готового сайта (без node_modules)
```

`id` — по паттерну (`agency-light-shader`), не по имени бренда в макете.

## Как класть

1. Классифицировать по TAXONOMY.md.
2. Если это доделанный сайт — класть **site/**, не черновой промпт.
3. Три файла: `meta.yaml`, `USAGE.md`, исходники в `site/`.
4. Строка в `etalons/index.yaml` и в `etalons/README.md`.
5. Коммит в `main`. Без веток-рубрик, без сборок, без `.env`.

Сюда не кладём: `node_modules`, `dist`, видео/фото исходники (только URL в коде), чаты.

## Как агенту выбирать

1. Класс задачи → `etalons/index.yaml`.
2. Прочитать `USAGE.md`.
3. Смотреть `site/` как эталон вёрстки и ритма.
4. Собрать работу под бриф заказчика. Бренд и тексты эталона не копировать.
